# 后台 MVP 边界与后续迭代候选

本文供后续开发后台的 Agent 接手使用。目标是守住当前 MVP 边界，并记录只有在触发条件出现后才值得增加的能力，避免提前扩张范围。

## 当前 MVP 已确认的边界

- 单用户个人系统，不引入账号、角色或权限管理。
- 使用独立的 `ADMIN_API_TOKEN`；纯 SPA 只在内存中保存 Token，刷新页面后重新输入。
- 使用现有只读列表接口验证 Token，不增加单独的登录验证接口。
- 后台与 API 同源部署，不开放跨域 CORS。
- 编辑交易时允许修改 `type` 和 `subcategory`，但不允许修改 `currency`。
- 分类使用后端契约中的固定集合，不增加分类列表或自定义分类 API。
- 统计仅使用现有今日和月度接口。

## 前端落地时必须完成

这些不是新的后端功能，应与实际前端构建产物一起完成：

1. 让 Caddy 托管前端静态资源并支持 SPA 路由回退。
2. 保持 `/api`、`/health`、`/docs*`、`/redoc` 和 `/openapi.json` 转发到 FastAPI。
3. 将前端生产构建接入 Docker 镜像或 Compose；在没有前端构建产物前不要提前修改当前可用的 Caddy 配置。
4. 本地开发通过前端开发服务器代理 `/api`，不要为此给 FastAPI 增加 CORS。

## 仅在触发条件出现后迭代

| 候选能力 | 触发条件 | 届时建议 |
| --- | --- | --- |
| 持久登录 | 频繁重新输入 Token 已明显影响使用 | 增加服务端 BFF/会话，以 `Secure`、`HttpOnly`、`SameSite` Cookie 保存会话；同时设计 CSRF 防护和会话失效机制 |
| 币种编辑或多币种统计 | 实际出现非 CNY 交易 | 先定义汇率和汇总语义，再开放 `currency` 修改；不要直接把不同币种金额相加 |
| 自定义分类 | 固定分类已无法覆盖真实使用 | 再设计分类实体、迁移和分类 API；当前不要只为下拉框增加读取固定分类的接口 |
| 年度或自定义区间统计 | 月度视图不足以回答实际问题 | 根据明确的页面查询需求增加最小统计接口 |
| 软删除或审计记录 | 发生误删，或需要追溯修改历史 | 再引入恢复与保留策略；当前永久删除继续依赖 UI 二次确认和数据库备份 |

除上述触发条件外，不应主动增加多用户、角色权限、审计平台、消息队列或独立前端服务。
